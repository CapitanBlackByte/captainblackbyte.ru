# Бот заявок

Клиент пишет в Telegram задачу, имя и контакт, заявка сохраняется и приходит менеджеру карточкой. Менеджер отвечает на карточку, и ответ уходит клиенту от имени бота. Внешних зависимостей нет, `npm install` не нужен.

Нужен Node.js 20.12 или новее. Проверено на Node.js 24.

## Запуск

1. Создайте бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. Скопируйте `.env.example` в `.env`, впишите токен в `BOT_TOKEN`, а свой Telegram-аккаунт в `MANAGER_USERNAME`.
3. Запустите бота:

   ```bash
   npm start
   ```

4. Напишите боту `/start` с указанного аккаунта. Заявки начнут приходить в этот чат, и там же можно проверить анкету глазами клиента.

Чтобы заявки приходили в группу, добавьте туда бота, отправьте в группе `/id@имя_бота` и впишите полученное число в `MANAGER_CHAT_ID`.

Токен нельзя никому показывать и нельзя добавлять в git: `.env` и `data/` в репозиторий не попадают.

## Работа на компьютере с Windows

Скрипт запускает бота в фоне и добавляет его в автозагрузку. Окно и приложение Claude для этого не нужны:

```bash
powershell -ExecutionPolicy Bypass -File scripts\windows-autostart.ps1
```

Повторный запуск скрипта перезапускает бота, это нужно после правок `.env`, кода или текстов. Остановить бота и убрать его из автозагрузки:

```bash
powershell -ExecutionPolicy Bypass -File scripts\windows-autostart.ps1 -Remove
```

Журнал работы лежит в `data\bot.log`. Персональных данных и токена в нём нет.

Бот работает, пока компьютер включён, выполнен вход в Windows и Telegram доступен, например через VPN. Если он выключен, Telegram хранит сообщения клиентов до 24 часов и отдаёт их при следующем запуске.

## Заявки с формы на сайте

Токен бота нельзя показывать браузеру, поэтому форма отправляет заявку на сервер сайта, а бот сам забирает её оттуда раз в несколько секунд и присылает менеджеру карточкой. Если бот выключен, заявка ждёт на сервере. После передачи она там удаляется. Если сервер не ответил, форма предлагает отправить заявку письмом.

На сервере сайта нужен Node.js 20.12 или новее, nginx и systemd. Скопируйте туда папку `inbox/` вместе с файлом `.env` и выполните в ней установку. Скрипт ставит службу, добавляет в настройки nginx адрес `/api/orders` и проверяет результат. Перед правкой настроек nginx он делает копию файла, а если nginx их не примет, возвращает всё как было:

```bash
sudo sh install.sh
```

Затем в `.env` бота укажите адрес сервера и перезапустите бота:

```
INBOX_URL=https://captainblackbyte.ru/api/orders
```

В `INBOX_TOKEN` бота и в `inbox/.env` должен быть один и тот же ключ.

Для проверки на своём компьютере приём заявок можно запустить из корня проекта. Локальный сайт сам передаёт ему запросы к `/api`, а в `.env` бота нужен адрес `http://127.0.0.1:8790/api/orders`:

```bash
node bot/inbox/inbox.mjs
```

В этом случае в `ALLOWED_ORIGIN` нужно указать адрес локального сайта, например `https://localhost:4173`.

## Перенос на сервер

Чтобы бот не зависел от компьютера, а данные оставались в России, нужен сервер в России. На него достаточно скопировать папку `bot/` вместе с `.env` и `data/`, а на компьютере выполнить скрипт с `-Remove`: две копии с одним токеном мешают друг другу.

Сервер должен доставать до Telegram. Проверка:

```bash
curl -m 10 https://api.telegram.org/bot000000:test/getMe
```

Ответ с кодом 401 значит, что всё в порядке. Таймаут значит, что сервер до Telegram не достаёт: так бывает в России. Тогда нужен релей на своём сервере за рубежом, а его адрес вписывается в `TELEGRAM_API_ROOT`. Через релей проходят токен и все сообщения, поэтому чужие релеи использовать нельзя, а свой нужно закрыть по IP сервера с ботом. Заявки при этом хранятся на сервере в России. Пример для Caddy, в работе с настоящим Telegram он не проверялся:

```
relay.example.com {
    @bot remote_ip 203.0.113.10
    handle @bot {
        reverse_proxy https://api.telegram.org {
            header_up Host api.telegram.org
        }
    }
    respond 403
}
```

Пример службы systemd, файл `/etc/systemd/system/captainblackbyte-bot.service`:

```ini
[Unit]
Description=Captain Black Byte orders bot
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/opt/captainblackbyte-bot
ExecStart=/usr/bin/node src/index.js
Restart=always
RestartSec=10
User=bot

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now captainblackbyte-bot
```

## Работа с заявками

| Действие | Как |
|---|---|
| Ответить клиенту | Ответить на карточку или на сообщение клиента |
| Сменить статус | Кнопки на карточке. Завершение и отказ просят подтверждения, клиент получает уведомление |
| Открытые заявки | `/orders` |
| Показать карточку снова | `/order_1001` или нажать на эту команду в списке |
| Удалить данные заявки | `/delete_1001` |

Сообщения клиента после отправки заявки приходят менеджеру ответом на её карточку. Кнопками статусов можно не пользоваться: на приём заявок они не влияют. Тексты меняются в `src/texts.js`.

## Данные и закон

Заявки, незаполненные анкеты и отметки о согласии хранятся в `data/state.json` там, где запущен бот, а заявки с формы до передачи боту ещё и в `data/inbox.json` на сервере сайта. Файл содержит персональные данные, поэтому его нужно регулярно копировать и никому не передавать. Незаполненные анкеты удаляются через 7 дней, а заявки через 3 года с последнего сообщения по ним: этот срок указан в политике на сайте и в тексте согласия, поэтому менять его нужно во всех трёх местах. Карточки в чате менеджера бот удалить не может, их нужно удалять вручную. Чтобы удалить данные клиента по его просьбе, отправьте `/delete_1001` с номером каждой его заявки. Сообщения в чате менеджера удаляются отдельно, в самом Telegram.

Запускайте бота только в России: закон о локализации требует хранить данные россиян в российских базах. Кроме этого нужны:

- политика обработки персональных данных на сайте (`privacy.html`), её адрес вписывается в `PRIVACY_URL`, и отдельный текст согласия для формы (`consent.html`);
- уведомление Роскомнадзора об обработке персональных данных;
- решение юриста про Telegram: это иностранный сервис, и карточка заявки хранится на его серверах, поэтому может понадобиться отдельное уведомление о трансграничной передаче;
- проверка текста согласия в `src/texts.js` юристом.

## Тесты

```bash
npm test
```

Тесты идут на локальной заглушке Telegram API, которая проверяет те же ограничения, что и настоящий API: длину сообщений, разметку HTML, размер данных на кнопках. Настоящий Telegram они не заменяют.
